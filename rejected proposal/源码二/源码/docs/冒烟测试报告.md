## 3. 发现并修复的问题

### BUG-01（已修复）：SQLite 模式下后端无法启动

- **现象**：`python run.py` 直接抛出 `TypeError: Invalid argument(s) 'pool_size' sent to create_engine()`，服务完全起不来。
- **原因**：`app/database.py` 对所有数据库统一传入了 `pool_size` / `pool_pre_ping` 连接池参数，而 SQLite（aiosqlite 方言）使用 NullPool，不接受这些参数；仅 MySQL 方向的参数校验逻辑不适用于开发模式。
- **影响**：README 宣称的"SQLite 零配置开发模式"实际不可用。
- **修复**：`app/database.py` 中按 `db_type` 分支——SQLite 走 NullPool 默认参数，MySQL 保留连接池配置。修复后 SQLite 与 MySQL 两种模式均正常。
- **修复位置**：`backend/app/database.py`（仅此一处改动，未修改其他任何业务代码）。

## 4. 核心功能验证明细

### 4.1 DAG 执行引擎（关键路径）

构建测试作业「CSV输入 → 字段拼接 → CSV输出」，上线后引擎自动完成：拓扑排序（`n1→n2→n3`）→ 逐节点执行 → 失败传播检查 → 结果落盘。

```
[engine] 拓扑排序完成，执行序: ['n1', 'n2', 'n3']
[engine] 节点 csv-input   完成: 5 行, 耗时 2ms
[engine] 节点 concat(字段拼接) 完成: 5 行, 耗时 0ms
[engine] 节点 csv-output  完成: 5 行, 耗时 1ms
[engine] 流水线执行完成: 3 成功, 0 失败, 总耗时 4ms
```

输出文件 `output.csv` 内容验证正确（`full_name` 字段为 A+B 拼接结果）：

```
first_name,last_name,age,full_name
Zhang,San,25,ZhangSan
Li,Si,30,LiSi
...
```

- 一次性作业执行完毕后状态自动回落 `offline`（生命周期语义正确）；
- 执行历史（`rows_processed`、耗时、日志）正确落库 SQLite。
