# 通用流处理任务管理平台 —— 数据库设计（废案 · Python + C++ 路线）

> 对应交付物：《数据库设计》
> 技术栈：SQLAlchemy 2.0（全异步） · 开发 SQLite / 生产 MySQL 8
> 源码位置：`backend/app/models/`

## 1. ER 设计

```
┌──────────┐          ┌──────────┐
│   user   │          │component │
│  用户表   │          │ 控件表    │
└────┬─────┘          └──────────┘
     │ created_by              （内置控件常驻内存注册表，
     │                          本表存用户自定义控件）
┌────▼─────┐
│   job    │
│  作业表   │  dag_config：JSON 字符串，存节点与连线
└────┬─────┘
     │ job_id
     │
┌────▼──────┐
│ execution │
│ 执行记录表 │  每次上线执行写一条，含日志与处理行数
└───────────┘
```

关系说明：

- `job.created_by → user.id`（作业归属人，可为空）
- `execution.job_id → job.id`（一个作业对应多次执行记录）
- `component` 独立：内置控件由 `@register_component` 装饰器注册在**内存注册表**，不落库；
  该表用于存放用户自定义控件，因此初始为空属正常。

## 2. 表结构设计

### 2.1 user —— 用户表

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INTEGER | PK, AUTO | 主键 |
| username | VARCHAR(50) | UNIQUE, NOT NULL | 登录用户名 |
| password | VARCHAR(255) | NOT NULL | 密码（存哈希） |
| email | VARCHAR(100) | NULL | 邮箱 |
| role | VARCHAR(20) | DEFAULT `user` | 角色：`user` / `admin` |
| created_at | DATETIME | DEFAULT now | 创建时间 |
| updated_at | DATETIME | DEFAULT now, ON UPDATE | 更新时间 |

### 2.2 component —— 控件表（用户自定义）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INTEGER | PK, AUTO | 主键 |
| name | VARCHAR(100) | UNIQUE, NOT NULL | 控件编码（如 `csv-input`） |
| display_name | VARCHAR(100) | NOT NULL | 显示名（如「CSV 输入」） |
| type | VARCHAR(20) | NOT NULL | 类别：`input` / `process` / `output` |
| config_schema | TEXT | NULL | 参数 JSON Schema，前端据此动态渲染表单 |
| description | TEXT | NULL | 描述 |
| icon | VARCHAR(50) | NULL | 图标标识 |
| created_at / updated_at | DATETIME | | 时间戳 |

> 内置 12 个控件（4 输入 + 4 处理 + 4 输出）不走本表，见 `backend/app/components/`。
> 本表为**空**是正常状态。

### 2.3 job —— 作业表

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INTEGER | PK, AUTO | 主键 |
| name | VARCHAR(100) | NOT NULL | 作业名 |
| description | TEXT | NULL | 描述 |
| status | VARCHAR(20) | DEFAULT `draft` | `draft` / `online` / `offline` / `error` |
| **dag_config** | TEXT | NULL | **DAG 定义（JSON 字符串）**：`{nodes:[...], edges:[...]}` |
| created_by | INTEGER | FK → user.id, NULL | 创建人 |
| created_at / updated_at | DATETIME | | 时间戳 |

DAG 结构示例：

```json
{
  "nodes": [
    {"id": "n1", "component_name": "csv-input",
     "position": {"x": 0, "y": 0},
     "config": {"path": "C:/tmp/in.csv", "separator": ",", "encoding": "utf-8"}},
    {"id": "n2", "component_name": "concat", "position": {"x": 200, "y": 0}, "config": {}},
    {"id": "n3", "component_name": "csv-output",
     "position": {"x": 400, "y": 0}, "config": {"path": "C:/tmp/out.csv"}}
  ],
  "edges": [
    {"id": "e1", "source": "n1", "target": "n2"},
    {"id": "e2", "source": "n2", "target": "n3"}
  ]
}
```

> `position` 为前端画布坐标，仅供可视化还原；引擎执行时只读 `component_name`、
> `config` 与 `edges`（拓扑排序后按序执行）。

### 2.4 execution —— 执行记录表

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INTEGER | PK, AUTO | 主键 |
| job_id | INTEGER | FK → job.id, NOT NULL | 所属作业 |
| status | VARCHAR(20) | DEFAULT `running` | `running` / `success` / `failed` |
| rows_processed | INTEGER | DEFAULT 0 | 本次处理行数 |
| started_at | DATETIME | DEFAULT now | 开始时间 |
| finished_at | DATETIME | NULL | 结束时间 |
| log | TEXT | NULL | 执行明细（JSON：各节点耗时与日志） |
| error_msg | TEXT | NULL | 失败原因 |

`log` 字段结构示例：

```json
{
  "elapsed": 0.077,
  "result": {
    "status": "success",
    "rows_processed": 6,
    "elapsed_ms": 76.6,
    "node_results": {"n1": {"status": "success", "rows": 2, "elapsed_ms": 51.3}},
    "logs": ["拓扑排序完成，执行序: ['n1', 'n2', 'n3']", "..."]
  }
}
```

## 3. 设计说明

### 3.1 双数据库模式

| 模式 | 数据库 | 用途 | 连接池 |
|---|---|---|---|
| 开发 | SQLite（aiosqlite） | 零配置启动，开箱即用 | NullPool（SQLite 不支持连接池参数） |
| 生产 | MySQL 8（aiomysql） | 持久化部署 | pool_size=10 + pool_pre_ping |

通过环境变量切换：`BS_DB_TYPE=mysql BS_DB_PASSWORD=xxx`。
`app/database.py` 按 `db_type` 分支构造引擎参数——SQLite 若误传 `pool_size`
会直接抛 `TypeError` 导致服务起不来（该问题已在冒烟测试中发现并修复，见冒烟报告 BUG-01）。

### 3.2 为什么 DAG 存 JSON 字符串而非拆表

DAG 是**整体读写**的最小单元（保存时整图覆盖、执行时整图加载），没有按节点/边单独查询的需求。
存 JSON 字符串避免了 `node` + `edge` 两张关联表的连接开销，也让前端画布数据可以原样落库、原样取出。
代价是无法用 SQL 按节点维度检索——在本题的场景规模下不需要。

### 3.3 为什么内置控件不落库

控件通过 `@register_component` 装饰器在应用启动时注册进内存注册表（`engine/component_base.py`），
`/api/components/built-in` 直接读内存返回。好处是新增控件只需加一个 Python 类、
重启即生效，无需维护数据库与代码的一致性。`component` 表留给"用户自定义控件"这一扩展场景。

### 3.4 执行记录与状态流转

每次 `POST /api/jobs/{id}/online` 产生一条 `execution`（`running`），执行结束后更新为
`success` / `failed` 并写入 `rows_processed` 与 `log`。作业自身的 `status` 同步流转为
`online` → `offline` / `error`。历史执行记录保留在表中，前端「作业详情」按 `job_id` 倒序展示。
