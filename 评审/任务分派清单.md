### T3 重建 md→docx 导出链路并重导 5 份 docx（1 人日，⚠️ 最高优先级）

**为什么最重要**：11 处 md 硬伤（DRAFT、裸表名 sys_user、10s、8 个基础控件、空文件 FAILED、真实 IP…）**只在 md 里修了，5 份 docx 全是旧内容**。评委打开的是 docx——不做这步，前面所有文档修复对评委不可见，分数停在 76。

**怎么做**（三步）：

1. **建导出链路**。仓库里没有导出脚本、本机没装 pandoc。两条路任选：
   - **装 pandoc**（推荐，排版可自定义参考样式）：`winget install pandoc` 或下载 portable 版，写 `scripts/md2docx.ps1` 固定命令行参数（toc、中文字体、样式参考 docx），入仓库；
   - **python-docx 写转换器**：按 `_audit/extract_docx.py` 逆向现有 docx 的样式结构，写 md→docx 转换脚本入仓库。
   - ⚠️ 不要手改 Word——不可复现，下次又会漂移。
2. **重导 5 份**：概要设计说明书 ← docs/01、数据库设计说明书 ← docs/02、部署文档 ← deploy/README-deploy.md、性能测试报告 ← docs/05（**等 T5 定稿后再导**）、完整测试报告 ← docs/08+10+11+12+13 合册。
3. **跑关键词校验**（必须全过）：

| 关键词 | 检查对象 | 期望 |
|---|---|---|
| `DRAFT` | 概要设计说明书.docx | 不存在 |
| `sys_user`（裸表名） | 数据库设计、概要设计 docx | 不存在（应为 `sp_sys_user`） |

| `空文件 FAILED` | 完整测试报告.docx | 不存在 |

**验收**：6 行全过 + 5 份 docx 修改时间晚于对应 md。

### T4 VM 重跑性能矩阵 + 采集原始证据（半天，一次实验解决三个待办）

**为什么值得跑**：评审卡在"49.0s/58.8s/46s 哪个是真的、内存四种说法、磁盘是否饱和"——这些争议靠翻旧记录无法解决，**重跑一遍拿新数据当唯一权威口径**是唯一干净的做法。顺带补齐横向扩展矩阵（现在只有 4 个数据点）和原始证据（50M 行一直没有日志）。

**怎么做**（VM 192.168.5.136 已开机、compose 栈在跑）：

1. **先采集环境证据**（一次性，也供 T8 用）：
   ```bash
   lscpu > env-lscpu.txt; free -h > env-free.txt
   df -h > env-df.txt; lsblk -d -o NAME,ROTA,SIZE > env-lsblk.txt
   docker version > env-docker.txt; docker compose version >> env-docker.txt
   ```
2. **跑矩阵**，每格 **3 次取中位数**（数据集用现有 `data/gen_csv.sh` 生成或复用 /data/bench 下已有的）：

| 数据集 | 并行度 | Worker 数 | 记录项 |
|---|---|---|---|
| M（1000 万行） | 1 | 1 | 端到端 / 吞吐 / 加速比 |
| M | 2 | 1 | 同上 |
| M | 4 | 1 | 同上 |
| M | 4 | 2 | 同上 |
| M | 6 | 3 | 同上 |
| L（5000 万行） | 1 | 1 | 同上 |
| L | 4 | 2 | 同上 |
| L | 6 | 3 | 同上 |

3. **跑 L 档时开 `iostat -x 1` 或 `sar -d 1` 留采样**，验证"磁盘到底饱和没有"（直接决定 T5 里 §4.2 怎么写）。
4. **留存原始日志**：每格运行的完整终端输出存 `logs/bench-matrix-<档位>-<日期>.log`，随源码包一起交付。

**验收**：矩阵 8 格都有数（中位数）；每格能指到一份原始日志；环境采集 6 份文件齐全。

### T6 撰写《项目创意与价值分析》（半天，纯写作，收益最直接）

**写什么**（3~5 页，四节，细节见整改清单 P1-4）：
1. **需求真实性**：行内 N 个系统重复建设流量接入/补数/转换的人力成本测算（人力 × 系统数 × 年）；
2. **竞品对比矩阵**：Flink SQL / StreamSets / NiFi / Kedro × 维度（上手门槛、部署成本、可视化编排、数据源丰富度、扩展方式、商用成本），**诚实写不如它们的维度**（exactly-once、生态成熟度）；
3. **差异化定位**：模式固定、高频重复、零代码的接入—加工—转发场景；分钟级上线；信创场景不引入重型引擎；
4. **推广与商业价值**：银行/证券/运营商/政务复用路径。

**产出**：`docs/00-项目创意与价值分析.md`，T3 导出链路建好后导出 docx 放入 deliverables/。

**验收**：含竞品矩阵 + 成本测算；`grep -r "竞品\|商业价值" docs/` 非空。
