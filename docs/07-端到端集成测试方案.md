### 0.2 通用工具函数（所有场景共用）

以下 bash 函数在 VM 上执行，建议先 `cat > ~/e2e-lib.sh` 保存，各场景 `source ~/e2e-lib.sh`：

```bash
BASE=http://localhost:8080/api
TOKEN=$(curl -s -X POST $BASE/auth/login -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"admin123"}' | sed -n 's/.*"token":"\([^"]*\)".*/\1/p')
AUTH="Authorization: Bearer $TOKEN"

mkjob() { # $1=作业名 $2=DAG的json文件 $3=并行度(默认1) → 输出作业ID
  local J=$(curl -s -X POST $BASE/jobs -H "$AUTH" -H "Content-Type: application/json" \
    -d "{\"name\":\"$1\",\"parallelism\":${3:-1}}")
  local JID=$(echo "$J" | sed -n 's/.*"id":\([0-9]*\).*/\1/p')
  curl -s -X PUT $BASE/jobs/$JID -H "$AUTH" -H "Content-Type: application/json" \
    --data-binary @"$2" > /dev/null
  echo "$JID"
}
online()  { curl -s -X POST $BASE/jobs/$1/online  -H "$AUTH" > /dev/null; }
offline() { curl -s -X POST $BASE/jobs/$1/offline -H "$AUTH" > /dev/null; }
status()  { curl -s $BASE/jobs/$1/instances -H "$AUTH" | sed -n 's/.*"status":"\([A-Z]*\)".*/\1/p' | head -1; }
wait_stop() { # 轮询到 STOPPED/FAILED，返回状态字
  while true; do local ST=$(status $1)
    case "$ST" in STOPPED|FAILED) echo "$ST"; return;; esac; sleep 2; done
}
cleanup() { offline $1; sleep 1; curl -s -X DELETE $BASE/jobs/$1 -H "$AUTH" > /dev/null; }
```

**重要**：DAG 里所有文件路径用**容器视角** `/data/...`（对应 VM 宿主机 `~/sp-data/...`）；
校验文件时在宿主机路径读。Kafka 地址在容器间用 `kafka:29092`。

### 0.3 控件参数 schema 查询（写 DAG 前必查，避免猜参数名）

```bash
TOKEN=...; curl -s http://localhost:8080/api/components -H "Authorization: Bearer $TOKEN" \
  | python3 -c "import json,sys; [print('==',c['code'],'\n',json.dumps(c['paramSchema'],ensure_ascii=False),'\n') for c in json.load(sys.stdin)]"
```
重点核对 `mysql-source / mysql-sink / field-map / data-mask / xml-to-json / json-to-xml` 的
required 参数名，按下发的 schema 填 DAG。

## 场景 1：MySQL → 字段映射 → Kafka（库表数据分发）

**业务含义**：业务库表经字段裁剪/改名后推送到消息队列，供下游订阅。

**数据准备**：
```bash
docker exec -i stream-platform-mysql-1 mysql -uroot -proot123 <<'SQL'
CREATE DATABASE IF NOT EXISTS biz;
CREATE TABLE IF NOT EXISTS biz.orders (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  order_no VARCHAR(32), cust_name VARCHAR(64), amount DECIMAL(10,2),
  created_at VARCHAR(32)
);
INSERT INTO biz.orders (order_no, cust_name, amount, created_at)
WITH RECURSIVE seq(n) AS (
  SELECT 1 UNION ALL SELECT n+1 FROM seq WHERE n < 100000
) SELECT CONCAT('SO', LPAD(n, 8, '0')), CONCAT('客户', n), n * 1.17, '2026-08-01' FROM seq;
SQL
```

**DAG**（写 /tmp/dag-s1.json，参数名以 0.3 查询结果为准）：
```json
{"dag":{"nodes":[
 {"id":"n1","componentCode":"mysql-source","params":{"url":"jdbc:mysql://mysql:3306/biz?useSSL=false&allowPublicKeyRetrieval=true","username":"root","password":"root123","table":"orders","batchSize":5000}},
 {"id":"n2","componentCode":"field-map","params":{"mapping":{"order_no":"orderNo","cust_name":"customer","amount":"amt"}}},
 {"id":"n3","componentCode":"kafka-sink","params":{"bootstrapServers":"kafka:29092","topic":"orders-topic"}}
],"edges":[{"from":"n1","to":"n2"},{"from":"n2","to":"n3"}]}}
```

**执行与校验**：
```bash
J=$(mkjob e2e-s1-mysql2kafka /tmp/dag-s1.json); online $J; ST=$(wait_stop $J); echo $ST   # 期望 STOPPED
# 校验：topic 消息数 = 100000
docker exec stream-platform-kafka-1 /opt/kafka/bin/kafka-get-offsets.sh \
  --bootstrap-server localhost:9092 --topic orders-topic | awk -F: '{s+=$3} END{print "msgs="s}'
# 抽样：首条消息应含改名后字段 orderNo/customer/amt
docker exec stream-platform-kafka-1 /opt/kafka/bin/kafka-console-consumer.sh \
  --bootstrap-server localhost:9092 --topic orders-topic --from-beginning --max-messages 2
cleanup $J
```
**通过标准**：状态 STOPPED；消息数=100000；抽样消息字段名已按映射改写。

## 场景 2：Kafka → 数据脱敏 → MySQL（消息消费入库 + 敏感字段保护）

**业务含义**：消费 Kafka 数据，手机号等敏感字段脱敏后入仓。直接使用场景 1 产出的 orders-topic。

**数据准备**（建目标表）：
```bash
docker exec -i stream-platform-mysql-1 mysql -uroot -proot123 \
  -e "CREATE TABLE IF NOT EXISTS biz.orders_dw (orderNo VARCHAR(32), customer VARCHAR(64), amt VARCHAR(32));"
```

**DAG**（/tmp/dag-s2.json）：
```json
{"dag":{"nodes":[
 {"id":"n1","componentCode":"kafka-source","params":{"bootstrapServers":"kafka:29092","topic":"orders-topic","groupId":"dw-g1","batchSize":5000}},
 {"id":"n2","componentCode":"data-mask","params":{"fields":["customer"],"maskType":"name"}},
 {"id":"n3","componentCode":"mysql-sink","params":{"url":"jdbc:mysql://mysql:3306/biz?useSSL=false&allowPublicKeyRetrieval=true","username":"root","password":"root123","table":"orders_dw","fields":["orderNo","customer","amt"]}}
],"edges":[{"from":"n1","to":"n2"},{"from":"n2","to":"n3"}]}}
```
（data-mask 的 fields/maskType 参数名以 0.3 schema 为准；mysql-sink 的 fields 为必填，指定写入列）

**执行与校验**（Kafka 源是无界流，读到足够行数后手动 offline 触发优雅停止）：
```bash
J=$(mkjob e2e-s2-kafka2mysql /tmp/dag-s2.json); online $J
for i in $(seq 1 60); do
  C=$(docker exec -i stream-platform-mysql-1 mysql -uroot -proot123 -N -e "SELECT COUNT(*) FROM biz.orders_dw")
  [ "$C" -ge 100000 ] && break; sleep 2
done
offline $J; ST=$(wait_stop $J); echo $ST   # 期望 STOPPED
# 校验1：行数
docker exec -i stream-platform-mysql-1 mysql -uroot -proot123 -N -e "SELECT COUNT(*) FROM biz.orders_dw"
# 校验2：脱敏生效（customer 不再是明文"客户N"）
docker exec -i stream-platform-mysql-1 mysql -uroot -proot123 -e "SELECT * FROM biz.orders_dw LIMIT 5"
cleanup $J
```
**通过标准**：orders_dw 行数=100000；customer 列已脱敏；无重复主键冲突报错（验证 at-least-once + 手动位移提交的正确性）。

## 场景 3：CSV → 字段拼接 + Redis 补数 → MySQL（文件批导入 + 维度关联）

**业务含义**：批量文件导入数仓，同时关联 Redis 维度表补全字段。

**数据准备**（Redis 预置 1000 个客户维度）：
```bash
{ for i in $(seq 1 1000); do echo "HSET user:v1_$i name name_$i city city_$i score $i"; done; } \
  | docker exec -i stream-platform-redis-1 redis-cli --pipe
docker exec -i stream-platform-mysql-1 mysql -uroot -proot123 \
  -e "CREATE TABLE IF NOT EXISTS biz.wide_rows (c1 VARCHAR(64), c2 VARCHAR(64), c3 VARCHAR(64), concat_col VARCHAR(255), name VARCHAR(64), city VARCHAR(64), score VARCHAR(16));"
```

**DAG**（/tmp/dag-s3.json）：
```json
{"dag":{"nodes":[
 {"id":"n1","componentCode":"csv-source","params":{"path":"/data/bench/in-100w.csv","hasHeader":true,"batchSize":5000}},
 {"id":"n2","componentCode":"field-concat","params":{"sourceFields":["c1","c2","c3"],"targetField":"concat_col","separator":"-"}},
 {"id":"n3","componentCode":"redis-enrich","params":{"host":"redis","port":6379,"keyField":"c1","keyPrefix":"user:","resultType":"fields"}},
 {"id":"n4","componentCode":"mysql-sink","params":{"url":"jdbc:mysql://mysql:3306/biz?useSSL=false&allowPublicKeyRetrieval=true","username":"root","password":"root123","table":"wide_rows","fields":["c1","c2","c3","concat_col","name","city","score"]}}
],"edges":[{"from":"n1","to":"n2"},{"from":"n2","to":"n3"},{"from":"n3","to":"n4"}]}}
```

**执行与校验**：
```bash
J=$(mkjob e2e-s3-csv-redis-mysql /tmp/dag-s3.json); online $J; ST=$(wait_stop $J); echo $ST
# 行数 = 1000000
docker exec -i stream-platform-mysql-1 mysql -uroot -proot123 -N -e "SELECT COUNT(*) FROM biz.wide_rows"
# 补数命中率恰好 1000；拼接列格式 c1-c2-c3
docker exec -i stream-platform-mysql-1 mysql -uroot -proot123 -N -e "SELECT COUNT(*) FROM biz.wide_rows WHERE name IS NOT NULL"
docker exec -i stream-platform-mysql-1 mysql -uroot -proot123 -e "SELECT * FROM biz.wide_rows LIMIT 3"
cleanup $J
```
**通过标准**：100 万行全量入库；name 非空行数=1000；concat_col=v1_N-v2_N-v3_N。

## 场景 4：MySQL → JSON 转 XML → CSV（格式转换导出）

**业务含义**：库表数据做协议格式转换后导出文件（对接遗留系统的典型需求）。

**DAG**（/tmp/dag-s4.json，xml 相关参数名以 0.3 schema 为准，如 rootTag/rowTag）：
```json
{"dag":{"nodes":[
 {"id":"n1","componentCode":"mysql-source","params":{"url":"jdbc:mysql://mysql:3306/biz?useSSL=false&allowPublicKeyRetrieval=true","username":"root","password":"root123","table":"orders","batchSize":5000}},
 {"id":"n2","componentCode":"json-to-xml","params":{}},
 {"id":"n3","componentCode":"csv-sink","params":{"path":"/data/e2e/s4-out.csv"}}
],"edges":[{"from":"n1","to":"n2"},{"from":"n2","to":"n3"}]}}
```

**执行与校验**：
```bash

head -3 ~/sp-data/e2e/s4-out.csv   # 内容应为 <order>...</order> XML 串

```
**通过标准**：行数正确；抽样行包含合法 XML。

## 场景 5：扇出拓扑稳定性（CSV → 拼接 → Kafka + MySQL 双写）

**业务含义**：一份数据同时分发到消息队列和数据库，验证 1→N→M 扇出拓扑下两路数据一致性。

**数据准备**：
```bash
docker exec stream-platform-kafka-1 /opt/kafka/bin/kafka-topics.sh \
  --bootstrap-server localhost:9092 --delete --topic fanout-topic 2>/dev/null
docker exec -i stream-platform-mysql-1 mysql -uroot -proot123 \
  -e "DROP TABLE IF EXISTS biz.fanout_t; CREATE TABLE biz.fanout_t AS SELECT * FROM biz.wide_rows WHERE 1=0;"
```

**DAG**（/tmp/dag-s5.json，一个 source 扇出到两个独立 sink 链）：
```json
{"dag":{"nodes":[
 {"id":"n1","componentCode":"csv-source","params":{"path":"/data/bench/in-100w.csv","hasHeader":true,"batchSize":5000}},
 {"id":"n2","componentCode":"field-concat","params":{"sourceFields":["c1","c2","c3"],"targetField":"concat_col","separator":"-"}},
 {"id":"n3","componentCode":"kafka-sink","params":{"bootstrapServers":"kafka:29092","topic":"fanout-topic"}},
 {"id":"n4","componentCode":"mysql-sink","params":{"url":"jdbc:mysql://mysql:3306/biz?useSSL=false&allowPublicKeyRetrieval=true","username":"root","password":"root123","table":"fanout_t","fields":["c1","c2","c3","concat_col"]}}
],"edges":[{"from":"n1","to":"n2"},{"from":"n2","to":"n3"},{"from":"n2","to":"n4"}]}}
```

**执行与校验**：
```bash
J=$(mkjob e2e-s5-fanout /tmp/dag-s5.json); online $J; ST=$(wait_stop $J); echo $ST
docker exec stream-platform-kafka-1 /opt/kafka/bin/kafka-get-offsets.sh \
  --bootstrap-server localhost:9092 --topic fanout-topic | awk -F: '{s+=$3} END{print "kafka="s}'   # 期望 1000000
docker exec -i stream-platform-mysql-1 mysql -uroot -proot123 -N -e "SELECT COUNT(*) FROM biz.fanout_t"  # 期望 1000000
cleanup $J
```
**通过标准**：两路输出各自完整 100 万行，无一路缺失/重复。

## 资源监控（每个场景执行期间同步做）

**方法 A：docker stats 定时采样**（推荐，最简单）。场景作业 online 后另开一个 SSH 窗口跑：
```bash
for i in $(seq 1 60); do
  docker stats --no-stream --format "{{.Name}} cpu={{.CPUPerc}} mem={{.MemUsage}}" \
    | grep -E 'worker|control-plane'; sleep 5
done | tee ~/e2e-stats-<场景名>.log
```
记录：worker 容器 CPU 峰值/均值、内存峰值（GB）。单 Worker 容器 JAVA_TOOL_OPTIONS 限了 -Xmx4g，内存不应超 4.5GB。

**方法 B：整机资源**（sysstat 已装）：
```bash
sar -u 5 60 > ~/e2e-cpu-<场景名>.log &   # CPU 每 5s 采样共 5 分钟
sar -r 5 60 > ~/e2e-mem-<场景名>.log &   # 内存
```

## 稳定性加测（时间充裕时做）

1. **Worker 故障自愈**：场景 3 运行中 `docker kill stream-platform-worker-1`，
   30s 后作业分片应被重置重派（如只有 1 个 worker，作业会等 worker 容器重启后恢复），
   最终 STOPPED 且行数正确（断点续传 at-least-once）。
2. **多 Worker 分片**：`docker compose up -d --scale worker=3`，
   场景 3 改为 parallelism=3 重建作业，观察 `/api/jobs/<id>/instances` 里 3 个分片
   是否分布到不同 worker 节点。
3. **长跑**：场景 2 不 offline，持续向 orders-topic 生产数据 10 分钟，观察 worker 内存是否平稳。

## 常见坑

- DAG 参数名写错 → 保存时 400 或运行时 FAILED，先按 0.3 查 schema 核对；
- **mysql-sink 必填 `fields`（写入列名数组）**，漏写时 PUT DAG 报 `缺少必填参数: fields`，online 后报 `DAG 不能为空`（无实例产生）——上线后务必查 `/api/jobs/<id>/instances` 确认实例已创建；
- 文件路径必须是容器视角 `/data/...`，写 `~/sp-data/...` 会报文件不存在；
- Kafka 地址容器内必须用 `kafka:29092`，不是 localhost:9092；
- Kafka 源是无界流，作业不会自己 STOPPED，数够行数后手动 offline；
- 作业 FAILED 时看实例的 errorMsg：`curl -s $BASE/jobs/<id>/instances -H "$AUTH"`，
  以及 worker 日志 `docker logs stream-platform-worker-1 --tail 50`。
