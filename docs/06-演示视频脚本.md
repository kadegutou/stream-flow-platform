## ⚠️ 拍摄方式（重要，先说清）

**实操片段分段录，后期剪辑拼接，不追求一镜到底。**

- 每个关键动作单独录一条（拖控件 / 连线 / 配参数 / 点保存…），失败就重录那一条
- 等待时间（作业跑完、worker 扩容、转场动画）**全部剪掉**，只留动作和结果
- 正式录制时按剪辑稿逐段拍摄，最后拼成流畅片段

这样每段都可控，避免"一次录 5 分钟、错一处全废"。

## 分镜 2 【讲解 · PPT】技术实现方式（0:25–1:10）

**画面**：PPT 一页——架构图（概要设计 §2）+ 两个设计取舍标注。

**讲解词**（45 秒，讲"怎么做"更要讲"为什么这么做"）：
"平台采用控制面与数据面分离架构：前端 React 加 React Flow 做可视化编排；控制面 Spring Boot 负责用户、控件、作业管理与调度；数据面是无状态 Worker 集群，执行引擎基于 JDK 21 虚拟线程实现**三段流水线**——读出、处理、写出并行，中间用有界队列做背压，按批传递数据。所有控件实现统一 SPI 接口，新数据源只需新增一个实现类。

两个关键取舍：**一是用 MySQL 而不是 ZooKeeper 做协调**——赛题规模下心跳加乐观锁足够，部署只要一个 compose；**二是用虚拟线程而不是异步回调**——每个分片是读-处理-写三个 I/O 密集角色，虚拟线程让单机轻松承载成百上千条流水线，代码还保持同步写法。"

## 分镜 5 【实拍】亮点：横向扩展与可靠性（2:45–3:20）

**画面**：Xshell 执行扩容命令 → `docker compose ps` 展示 3 个 Worker → 切浏览器监控页展示多 Worker 分摊。

```bash
cd ~/stream-platform/deploy
docker compose up -d --scale worker=3
docker compose ps
```

**讲解词**：
"横向扩展只需增加 Worker：一条命令从 1 个扩到 3 个。作业按并行度切片——Kafka 按分区、CSV/HDFS 按字节区间、Excel 按行区间、JDBC 按分片列取值区间——调度器自动均衡到各节点。可靠性方面：Worker 心跳超时自动重派分片；文件作业记录字节/行号偏移，崩溃后断点续传；fencing token 防止网络分区下的重复执行。整体语义是 at-least-once。"

> ⚠️ 并行度对比只用 1000 万行档：100 万行时固定调度开销占大头，p1/p4 打平；1000 万行档 p4 稳定快一倍（28.5s vs 58.8s）。被问到就答"小任务并行不划算，调度有固定成本"。

## 分镜 6 【讲解 · PPT + 加速画面】性能测试方案与结果（3:20–4:05）

**画面**：PPT 关键表格（三档数据量、吞吐、横向扩展对比）+ `bench.sh` 实跑画面（**加速播放**）。

**讲解词**：
"性能测试用自动化脚本：程序生成三档数据量，经 REST API 建作业、上线、计时、校验输出，全程无人值守、可复现。

结果方面，csv 读取、字段拼接、写出的主场景——5000 万行、5.9GB，6 分片、3 个 Worker，端到端 90 秒，稳态吞吐 55.6 万行每秒、81.7MB/s，行数校验零丢失零重复。横向扩展上，1000 万行档从单分片 58.8 秒降到 4 分片 28.5 秒，吞吐随节点近线性增长。

分析表明瓶颈收敛于磁盘物理带宽，引擎自身不构成瓶颈——这也是平台提供分片能力的原因。"

### 分镜 6：性能实测

```bash
cd ~/stream-platform
# 主镜头：5000 万行 × 6 分片 × 3 Worker（约 90 秒）
PARALLELISM=6 OUT=/data/bench/bench-out-50m.csv OUT_HOST=$HOME/sp-data/bench/bench-out-50m.csv bash scripts/bench.sh /data/bench/in-5000w.csv 50000000 50m
# 省时备选（约 30 秒）：
PARALLELISM=4 OUT=/data/bench/bench-out-10m.csv OUT_HOST=$HOME/sp-data/bench/bench-out-10m.csv bash scripts/bench.sh /data/bench/in-1000w.csv 10000000 10m
```

> ⚠️ 命令**写成一行**（不要用 `\` 续行）——粘贴多行命令时续行符常处理失败，报 `Command ' bash' not found`。

输出形如：`[50m] 行数=50000000 端到端=90.0s 吞吐=555555行/s (81.7 MB/s) 输出校验=50000006行/...字节`
