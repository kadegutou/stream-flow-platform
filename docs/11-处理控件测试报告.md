### 4.3 data-mask（脱敏算法正确性）

| 策略 | 输入 | 实际输出 | 期望 | 结果 |
|---|---|---|---|---|
| mask-middle | `13812345678` (11位) | `138****5678` | 前3后4 | PASS |
| mask-middle | `13987654321` (11位) | `139****4321` | 前3后4 | PASS |
| mask-middle | `138` (len=3 边界) | `1**` | 首字符+星 | PASS |
| mask-middle | `12345` (len=5 边界) | `1***5` | 首尾各1 | PASS |
| mask-middle | NULL | NULL（不脱敏不报错） | NULL | PASS |
| hide | `user1@test.com` | `***` | `***` | PASS |
| hide | NULL | NULL | NULL | PASS |
| hash | `user1`（ASCII） | 与 MySQL `SHA2(name,256)` 完全一致 | SHA-256 hex | PASS |
| hash | `用户😀名`（UTF-8 含 emoji） | 与 `SHA2(utf8mb4 转码, 256)` 一致 | SHA-256 hex | PASS |
| hash | 5000 字符超长串 | 64 位 hex，算法不变 | SHA-256 hex | PASS |
| hash | NULL | NULL | NULL | PASS |

**脱敏算法结论**：mask-middle 按长度自适应分段（len≥8 保留尾 4 位，len≤3 保留首字符），hash 为标准 SHA-256（UTF-8 字节，小写 hex，与 MySQL SHA2 函数可互验），hide 恒为 `***`；空值一律原样通过。

## 5. 需关注的行为特性（非缺陷，使用时需知）

### 5.1 XML 往返后数值/布尔退化为字符串

| 原始 JSON | 往返后 |
|---|---|
| `"age": 30` | `"age": "30"` |
| `"active": true` | `"active": "true"` |
| `"score": 99.5` | `"score": "99.5"` |
| `"tags": ["a","b"]` | `["a", "b"]`（数组保真） |

**原因**：XML 文本节点天然无类型信息，Woodstox/Jackson 读回时按字符串处理。**影响**：若下游对数值类型敏感，需在 XML→JSON 后自行做类型转换。字符串值、嵌套结构、数组均无损。

### 5.2 xml-to-json 的根元素解包语义

`<person><name>Alice</name></person>` → `{"name":"Alice"}`（根元素名 `person` 不保留，其子元素直接成为 JSON 根）。这是 Jackson XmlMapper readTree 的标准语义；json-to-xml 方向则统一以 `<ObjectNode>` 为根。**若需保留根元素名，需在外层再包一层对象。**

### 5.3 单行坏数据导致整作业失败（无逐行隔离）

批内任意一行解析失败（如非法 JSON），整个分片作业立即 FAILED，错误信息精确定位到行内容与列号（`Unexpected character ('i' ...) line: 1, column: 2`）。这是**快速失败**设计：优点是不会静默丢弃或错误转换数据，缺点是脏数据需先清洗。错误恢复已在上轮 IO 测试验证（修复数据后 offline→online 同一作业即可恢复）。

## 8. 性能测试

万行数据经 **field-concat → data-mask → field-map → mysql-sink** 三处理器链式处理：

| 指标 | 数值 |
|---|---|
| 数据规模 | 10,003 行 |
| 端到端耗时 | 12 s |
| 吞吐 | **约 833 行/s**（含 MySQL 读写） |
| 数据完整性 | 输出行数 = 源行数，抽检值正确 |

> 处理控件本身为内存计算，吞吐瓶颈主要在 JDBC 读写；万行级数据量下 6 种控件均无性能异常。如需区分数值计算/序列化开销，建议做百万行级基准。

## 10. 结论

1. **逻辑正确性**：6 种处理控件共 62 项断言全部通过，字段拼接/映射/脱敏/JSON-XML 互转/Redis 补数的输出与期望值逐项精确一致。
2. **转换准确性**：JSON↔XML 字段映射完整（含嵌套对象、数组、特殊字符、中文、emoji）；唯一需注意的是数值/布尔经 XML 往返后退化为字符串（§5.1）及根元素解包语义（§5.2）。
3. **脱敏算法**：mask-middle 分段规则、SHA-256（UTF-8）、hide 三种策略均与标准实现可互验，空值安全。
4. **数据完整性**：空值原样通过、超长字符串无损、特殊字符字节级无损、Redis 未命中不丢行。
5. **容错性**：非法输入/非法参数/依赖不可达均快速失败且错误信息可定位，失败后无脏数据；修复后重新上线即可恢复。

**总体评价：处理控件功能与容错行为符合设计预期，可投入使用。**
