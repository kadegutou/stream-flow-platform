# 通用流处理任务管理平台 —— 测试报告

## 1. 测试概述

本报告汇总平台的全部测试活动与结果。测试在真实容器化部署环境（Docker Compose：
控制面 + Worker + MySQL 8.4 + Kafka 3.9.1 + Redis 7，外部增装 PostgreSQL 16 /
Oracle 21c XE / HDFS 3.3.6）上进行，覆盖功能正确性、边缘场景、并发、容错恢复
与性能五个维度。

### 1.1 测试覆盖总览

| 测试领域 | 章节 | 覆盖范围 | 数据规模 | 结论 |
|---|---|---|---|---|
| 端到端集成 | 第 2 章 | 5 个核心业务场景（MySQL→Kafka、Kafka→脱敏→MySQL、CSV→补数→MySQL、格式转换导出、扇出双写） | 100 万行级 | 全部通过 |
| 输入/输出控件 | 第 3 章 | 7 输入 + 7 输出控件 × MySQL/PG/Oracle/HDFS/Kafka/CSV/Excel | 万行级 + 边缘用例 | 14/14 通过 |
| 处理控件 | 第 4 章 | 6 个处理控件，62 项精确断言（拼接/映射/脱敏/JSON↔XML/补数） | 边界值 + 故障注入 | 62/62 通过 |
| 数据质量与异常 | 第 5 章 | 10 用例：坏行、缺列、空文件、类型冲突、非法协议、脏消息、对账、kill 恢复、吞吐、长跑 | 最大 1000 万行 | 全部符合预期 |
| 性能基准 | 见《性能测试报告》 | csv→拼接→csv 三档规模 + 分片横向扩展 | 最大 5000 万行（5.9GB） | 55.6 万行/s |

### 1.2 测试驱动的问题修复闭环

测试过程中发现的平台侧问题均已修复并回归验证：

| 问题 | 发现环节 | 修复 |
|---|---|---|
| kill Worker 断点恢复丢失数据（断点上报了 Source 预读位置） | 第 5 章 t09_08 | 断点改为「全部 Sink 写完的批次偏移」；fencing 拒绝立即中止防双写；回归：100 万行零丢失、重复仅 1%（at-least-once 预期） |
| 挂起实例拖慢后续作业 | 第 5 章 | 随上述修复消除（中止不再排空缓冲队列） |
| 空文件（0 字节）导致作业 FAILED | 第 5 章 t09_03 | csv/hdfs 源改为优雅 STOPPED（0 行） |
| 并行度>1 时 JDBC/Excel 源产生重复数据 | 第 3 章并发测试 | 控制面强制校验：不支持分片的源并行度=1 |
| 下线时未派发分片使实例永久 STOPPING | 第 5 章 | 未派发分片直接置 STOPPED |

> 上述修复均已合入主干并回归通过；测试脚本（`scripts/` 下 bench.sh、
> kafka-redis-verify.sh、t09-08-repro.sh 等）随源码包交付，全部可重复执行。
